ЦЕЛЬ
----------------------------------------------------------------
    Создать слой нормализации данных для маркетплейсов,
    который будет преобразовывать сокращённые значения
    свойств товаров из 1С в полноценные читаемые значения.

    Пример:
        "чорн/рефл" -> "чорний/рефлективний"
        "проз/чор/сір" -> "прозорий/чорний/сірий"

----------------------------------------------------------------
ОСНОВНАЯ ИДЕЯ
----------------------------------------------------------------
    Система НЕ изменяет оригинальные данные из 1С.

    Исходные значения продолжают храниться в: __features_values.value

    Нормализация выполняется "на лету" во время генерации данных для маркетплейса.

----------------------------------------------------------------
ПРИНЦИП РАБОТЫ
----------------------------------------------------------------
    Система работает по token-based модели.

    Пример:

        Исходное значение: "проз/чор/сір"

    Этапы обработки:
        1. Разбить строку на токены: [проз, чор, сір]

    2. Для каждого токена найти полное значение:
        проз -> прозорий
        чор -> чорний
        сір  -> сірий

    3. Собрать результат: "прозорий/чорний/сірий"

----------------------------------------------------------------
СЛОВАРЬ СОКРАЩЕНИЙ
----------------------------------------------------------------
    Создать таблицу:

    __feature_token_dictionary

    Поля:
        - id
        - token
        - normalized_value

    Пример:
        чорн  -> чорний
        рефл  -> рефлективний
        сір   -> сірий
        проз  -> прозорий

----------------------------------------------------------------
ПОЧЕМУ ИСПОЛЬЗУЕТСЯ TOKEN-BASED ПОДХОД
----------------------------------------------------------------
    Система хранит только атомарные сокращения, а не готовые комбинации.

    Это позволяет:
        - автоматически обрабатывать новые комбинации
        - не хранить тысячи вариантов
        - упростить поддержку
        - расширять словарь постепенно

    Пример:
        Если система знает:
            чорн -> чорний
            жовт -> жовтий
            рефл -> рефлективний

        то строка: "чорн/жовт/рефл"
        будет автоматически преобразована в: "чорний/жовтий/рефлективний"
        без добавления новой записи в БД.

----------------------------------------------------------------
ГДЕ ВЫПОЛНЯЕТСЯ НОРМАЛИЗАЦИЯ
----------------------------------------------------------------
    Во время генерации XML для Rozetka.

    Преимущества:
        - не изменяются данные 1С
        - не требуется переимпорт
        - легко тестировать
        - легко обновлять словарь
        - изменения сразу применяются ко всем товарам

----------------------------------------------------------------
КЕШИРОВАНИЕ
----------------------------------------------------------------
    Словарь сокращений загружать в память одним SQL запросом.

    Далее поиск должен выполняться через PHP массив, а не через SQL запросы для каждого токена.

----------------------------------------------------------------
АРХИТЕКТУРА
----------------------------------------------------------------
    Источник данных:
        1С -> __features_values.value

    Слой нормализации:
        normalizeFeatureValue($value, $marketplace)

    Результат:
        готовое значение для маркетплейса.

----------------------------------------------------------------
ПЕРВАЯ ВЕРСИЯ МОДУЛЯ (V1)
----------------------------------------------------------------
    Текущая версия модуля НЕ учитывает:
        - сложные исключения
        - зависимость сокращений от feature_id
        - неоднозначные сокращения
        - специальные правила сборки
        - логирование неизвестных токенов
        - preprocessing сложных разделителей

    Основная задача V1:
        создать простую, стабильную и расширяемую основу.

----------------------------------------------------------------
РАСШИРЕНИЕ В БУДУЩЕМ
----------------------------------------------------------------
    Архитектура должна позволять в будущем добавить:
        - слой исключений
        - контекстную обработку feature_id
        - preprocessing значений
        - лог неизвестных токенов
        - специальные правила сборки
        - разные правила для разных маркетплейсов

----------------------------------------------------------------
ИТОГ
----------------------------------------------------------------
    Модуль представляет собой
        не систему replace(), а полноценный слой нормализации данных.

    Основная идея:
        нормализуются не готовые строки, а отдельные токены,
        из которых затем собирается итоговое значение.
